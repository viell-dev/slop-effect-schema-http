# What's in 0.16

This article describes unreleased work for `0.16.0`; `0.15.0` remains the published release.

This batch extends constructor-default validation through optional/nullable object alternatives,
sparse own array cells and an own data iterator equal to the native array iterator. Invalid aliases
in these covered profiles now refuse before dispatch instead of sending a generated default. The
same whole-decoding rule can refuse mixed-side input or change successful output, so this is one
breaking release. It does not finish
[#170](https://github.com/viell-dev/slop-effect-schema-http/issues/170).

Use [Schema-backed input](../schema-input.md) for the complete current contract and retained limits.
The [release family](./index.md#schema-input-hardening) distinguishes this batch from earlier
extensions and 0.15's separate array-normalization repair. The [version policy](../versions.md)
explains updates; the [changelog](../changelog.md) includes compatible fixes grouped into this
release.

On 0.15, `invalid` prepared `[{"page_size":"25"}]`. On 0.16 it fails with `SchemaError` before
dispatch. Both valid calls prepare `[{"page_size":"5"}]`; the isolated omission still prepares
`[{"page_size":"25"}]`. A constructor default is not a decoding default: whole decoding can leave an
omitted limit absent when another item establishes an encoded reading.

The message can call `page_size` an excess property: when the additional whole decoder fails,
preparation retains the original strict refusal. For field-value feedback under your form's names,
validate with [an explicit decoded mapping](#validate-a-decoded-mapping) before preparation.

The extension also covers nullable/nullish elements, tuple elements, eligible object ancestors and
closed object alternatives beside unencoded primitives. Nullable roots can establish the existing
root checks too. It adds no constructor replay or nested fieldwise ownership rule.

## Follow sparse own cells and native own iterators

Holes do not move a supplied own cell, and an exact native own iterator does not change that cell's
schema:

<<< ../../examples/migration-0-16.ts#sparse-iterator

On 0.15, these calls prepared `[null,{"page_size":"25"}]` and `[{"page_size":"25"}]`. On 0.16 both
refuse. Valid encoded `"05"` and decoded `5` retain `5`; an isolated omitted object retains `25`.
Sparse JSON retains its null position, and the caller's hole and length remain unchanged.

Only own data cells of ordinary or null-prototype arrays supply evidence, including hidden/frozen
cells. Holes and inherited cells supply none. Another own cell can nevertheless establish a whole
read that validates an inherited neighbor. Native own iterator data may be hidden, enumerable or
frozen; a wrapper, bound function, different native iterator or accessor remains excluded. Evidence
is invalidated if identities, descriptors or the native prototype iterator change. No caller
iterator or getter runs to collect this evidence; ordinary schema processing can still read getters.

## Bounds and remaining work

Only unencoded primitive union members that cannot consume an object are transparent: String,
Number, Boolean, BigInt, Symbol, UniqueSymbol, Literal, Enum, TemplateLiteral, Null, Undefined and
Never. `Void` can consume a supplied object and is excluded. Encoded primitives, primitive encoding
intermediates, open/opaque/suspended alternatives and array-shaped parent members remain excluded.
An alternative that is itself a primitive-only union remains excluded at both terminal and ancestor
levels. The member rule also covers a codec's closed nullable object encoding view, such as
`NullOr(Struct)`: invalid supplied aliases can now refuse there too; valid encoded/decoded values
and isolated omissions retain their results.

The initial whole constructor and actual original strict writer must succeed before a stable
caller/path/write permits whole decoding. Root fieldwise construction retains the original strict
refusal after its already-failed whole decoder; it does not replay that decoder. Whole decoding can
repeat checks and services, and existing defaults/effects can run before refusal. Output arrays must
still have matching length and dense own data cells. Sparse capture visits own keys rather than
allocating by array length.

Distinct declarations of the same normalized JavaScript key remain ambiguous, including numeric `1`
and string `"1"`. Their aliases can still be replaced by defaults. Accessors, subclasses, custom
prototypes/iterators, changing paths and unsupported construction phases also remain under #170.
Broader #143 selection/preservation limits remain separate. See the [active limits and
recovery](../schema-input.md#active-limits-and-recovery) before relying on a profile outside the
accepted batch.
