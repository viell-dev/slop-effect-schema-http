# What's in 0.14

Runtime extension of #170: stable dense array and tuple positions now connect the caller alias to
the actual constructor output. The changed dimension is the positional ancestor, after direct
objects and parent unions. Sparse/custom-iterator arrays and unsupported preparation routes remain
outside this validation.

The [version policy](../versions.md) covers updates, and the [changelog](../changelog.md) records
the changes. The [0.13 article](./0.13.md) describes the earlier parent-union extension and its
remaining distinct-declaration limit.

Compare the [related release family](./index.md#schema-input-hardening); use [Schema-backed
input](../schema-input.md) and [Schema-backed groups](../schema-groups.md) for today's contract and
active limits. The running schema below makes the changed route, container or layer directly
comparable with the previous release.

## Keep a complete side

Validation reads the whole array. A runtime mixed value such as `[{"limit":2},{"page_size":"05"}]`
previously wrote the second filter as `25`; it now refuses because the first item does not fit the
encoded side. `Request.Input` already excludes this mixed literal statically; JavaScript or a cast
can still reach the runtime boundary. Use a complete encoded or decoded array, or validate a named
mapping to decoded values below.

A whole encoded read also uses encoded names in a neighboring item supplied under both names:

<<< ../../examples/migration-0-14.ts#dual-names

This nonliteral input typechecks without a cast. On 0.13 it prepared `/pages/1/25`; on 0.14 it
prepares `/pages/2/25`. The same dual-name item alone, or beside a decoded/default item, still uses
`1`. The encoded-only sibling establishes a whole read that uses `page_size` throughout the group.

Decoded-name preference belongs to a selected constructor/decoded reading route. It does not apply
to every whole encoded read. This is a [known conflicting-alias
limit](https://github.com/viell-dev/slop-effect-schema-http/issues/143#issuecomment-6735302019), not
proof that both supplied values agree or a conflict-refusal fix. Give one complete side or validate
a decoded mapping; do not depend on which conflicting value happens to win.

## Bounds and remaining work

The proof accepts dense ordinary arrays with stable own data indices and length, including frozen,
null-prototype and nonenumerable positions. It captures all own keys, descriptors and identities
without cloning the caller graph or running iterators/getters for evidence. Static element/rest
metadata runs no schema checks, defaults or suspensions.

The initial whole constructor and original strict writer must actually succeed. One coherent stable
caller/path/output write stays selected; output correspondence is checked at selection, then only
caller evidence is retained through whole decoding and loss/sibling checks. Construction is not
replayed. Whole decoding can repeat checks and services; existing effects may run before refusal.
Strict-success, root proof, actual member-fieldwise consumption and writer-fallback priorities stay
intact.

Sparse/accessor/inherited/subclass/changing/custom-iterator arrays, array-shaped parent union
members, group transformations, opaque/suspended ancestors and unsupported member/fieldwise phases
remain outside this extension under
[#170](https://github.com/viell-dev/slop-effect-schema-http/issues/170). The distinct
normalized-declaration default substitution disclosed in 0.13 also remains open. Use validated
decoded values for affected schemas. Broader [schema/input
gaps](https://github.com/viell-dev/slop-effect-schema-http/issues/143) remain separate; this is not
general per-element recovery or inferred alias equality. [Limits and recovery](../limits.md) records
the current boundaries and alternatives.
