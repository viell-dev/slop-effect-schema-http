# What's in 0.12

Runtime extension of #170: the initial-constructor check can now follow an unchanged direct-object
field to the ignored alias. The changed dimension is nesting below a direct object. Root fieldwise
recovery from 0.11 remains a separate route and does not become general nested recovery.

The [version policy](../versions.md) covers updates, and the [changelog](../changelog.md) records
the changes. The earlier [0.10 input-type migration](./0.10.md) still applies; this release changes
how covered nested values are read at run time.

Compare the [related release family](./index.md#schema-input-hardening); use [Schema-backed
input](../schema-input.md) and [Schema-backed groups](../schema-groups.md) for today's contract and
active limits. The running schema below makes the changed route, container or layer directly
comparable with the previous release.

## Bounds and schema effects

The additional proof follows declared fields through finite closed, untransformed direct-object
ancestors. It captures stable own-data links, object identities, descriptors and prototypes, then
requires the original successful initial whole construction and successful strict writing. The same
path must actually contain an encoded-only terminal field in the output. One consistent witness is
kept through whole-schema decoding and the existing loss checks.

Whole decoding can run schema checks and services again; existing defaults and writers can run
before refusal, and their effects are not undone. Construction is not replayed. Strict-success
routes, writer-failure fallback, raw defaults and the earlier root/fieldwise checks retain their
behavior. This release adds no alias map or equality rule for arbitrary transformations.

A root fieldwise route can already decode a nested value correctly through its property reader. That
route keeps its existing meaning and cannot establish this constructor-only proof. The [0.11
fieldwise migration](./0.11.md) still describes root aliases beside mixed common fields.

On 0.12, parent unions, arrays, declarations/classes, opaque or suspended ancestors, and transformed
ancestors remain outside this extension. [0.13](./0.13.md) adds eligible closed untransformed parent
unions where every member declaring a field uses the same field schema. Distinct declarations and
the other unsupported paths remain. Inherited/accessor links, iterable or changing objects,
ambiguous terminal names and unsupported member/fieldwise routes also remain bounded under
[#170](https://github.com/viell-dev/slop-effect-schema-http/issues/170). Supply decoded values or a
validated decoded mapping for affected schemas. Reading inside opaque values remains schema-owned.
The broader [schema/input gaps](https://github.com/viell-dev/slop-effect-schema-http/issues/143)
remain open. [Limits and recovery](../limits.md) records the supported checks and workarounds.
