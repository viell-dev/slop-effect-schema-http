# What's in 0.5

Effect Schema HTTP 0.5 refuses more raw query/header edits that would disappear during preparation.
A direct struct can supply an omitted field while decoding, choosing fieldwise input or encoding, as
well as through a constructor default. When its successful output proves that a later raw edit would
be replaced, the request now fails with `Request.InvalidRequest` before dispatch.

`0.5.0` is a breaking release. Read the migration below before updating from `0.4`. The [version
policy](../versions.md) covers installation and updates, and the [detailed
changelog](../changelog.md) records the changes.

On `0.4`, compiling `ineffectiveEdit` with `{}` sent `?limit=25`: the later raw `5` disappeared. On
`0.5`, that preparation fails and names `limit`. The same rule applies to a raw append or removal,
and to header names compared without case.

The check uses the successful encoded result. It does not need constructor-default metadata, and it
does not evaluate a default, transformation, getter or iterator again. This also covers a field
generated only by its encoder and a constructor default supplied after fieldwise input decoding. A
failed route that supplies no output field proves no conflict.

## The proof stays local

The check covers explicit fields of a direct struct with the same input and output names. Before
preparation, the caller must have left the field absent or supplied an own data property containing
`undefined`. Successful non-iterable output must then hold an own enumerable data value under that
name. The existing per-binding record establishes that the raw edit came after this binding.

Iterable output uses the entries it yields. Its own string properties do not establish what is sent,
so this proof leaves it to the existing iterable path. Generator-based declarations remain
supported; a constructor-filled own property beside an empty generator no longer causes this
particular false refusal.

Group transformations such as `Schema.encodeKeys`, classes, unions, accessor and inherited input
properties remain outside the proof. Renamed defaults can still replace a raw edit, and conflicting
decoded/encoded aliases and the two known union-selection false refusals remain tracked in
[#143](https://github.com/viell-dev/slop-effect-schema-http/issues/143). Inside opaque values, the
schema's own reading still applies. See the [Request guide](../modules/request.md) and [Limits and
recovery](../limits.md) for the complete boundaries.
