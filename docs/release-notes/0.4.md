# What's in 0.4

Effect Schema HTTP 0.4 lets you leave an empty query or header group out of a call. It also fixes
two ways a field could disappear: a raw edit overwritten by a constructor default, and a field
beside a transformed union tag. Tags can now choose a union member by their encoded names too.

`0.4.0` is a breaking release. Read the migration checks below before updating from `0.3`. The
[version policy](../versions.md) covers installation and updates, and the [detailed
changelog](../changelog.md) records the individual changes.

This applies to query and headers, including all-optional structs, constructor defaults, and a union
with a member that accepts an empty object. Stacked schemas allow omission only when every binding
does. A required field still needs input even when a raw default is set in the definition. Path and
body inputs keep their keys, and `execute` still needs its argument.

An omitted group is validated as `{}`. A refinement can therefore refuse it even when the types
permit omission, just as it refuses an explicit empty group. See the [Request
guide](../modules/request.md) for the complete input rules.

### Update generic input constraints

This widens the inferred request input type. Ordinary calls keep working, but a generic helper whose
input constraint requires `headers` or `query` can stop compiling when that group becomes optional.

helper genuinely needs a supplied field, keep that field required in the request schema. The hostile
suite's Digest helper exposed this compiler incompatibility, so the input change is included in this
breaking release.

The schema validates the resulting input normally. A caller can also pass the field directly.

This is a check of what the current preparation actually did, rather than a claim that every
constructor default always writes its field. It uses the successful construction and encoding
results without running the default again. A failed or `undefined` default, an encoding that omits
the field, or a decoding fallback that bypasses construction does not supply that evidence.

The initial check covers direct structs. Classes, unions, renamed groups and other whole-object
transformations retain their stated limits; this release does not infer field correspondence through
them. Read the [design contract](../design.md#a-schema-states-the-shape-of-its-group) when combining
raw edits with these schemas.

## Tags on the encoded side

A required literal tag can choose through its encoded name. For a schema that renames `kind` to `k`,
a value such as `{ k: "c", x }` can now send `?k=c` when only a different tag's member states `x`.
`0.3` could refuse that value as a field it could not keep. The tag already rules that member out,
so its extra field is stripped, as for the same tag on the decoded side.

Both constructor and encoded views must rule a member out before its fields go. A missing tag with a
constructor default leaves that view possible; the default is never evaluated to guess a member.

## Limits that remain

This release does not resolve every schema and raw-value interaction in
[#143](https://github.com/viell-dev/slop-effect-schema-http/issues/143). In particular, giving a
renamed field under both names still keeps decoded precedence, a decoding default hidden by a group
rename can still replace a later raw edit, and some combinations of stacked schemas and opaque
values still refuse values a wider member could hold. Choose one side's names, bind the intended
member directly where necessary, and follow the [design contract](../design.md) for the precise
boundaries.

Inside opaque values such as text given as text, a `Map` or an `Option`, the schema's own reading
continues to apply. The client and platform limits in [Limits and recovery](../limits.md) also
remain, including the upstream redirect lifetime defect.

## Low-level preparation extensions

`Request.Draft` now carries `editedFields`, the per-binding record used by the constructor-default
check. An extension that spreads the draft it receives preserves this automatically. Code that
constructs a draft object from scratch must initialize it with `editedFields: new Map()` and keep
the record when preparing a derived draft. Ordinary request combinators need no change.
