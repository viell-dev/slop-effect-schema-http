# What's in 0.11

Effect Schema HTTP 0.11 refuses a further constructor-default overwrite during fieldwise recovery. A
supplied encoded alias can no longer disappear into a default in the covered closed-root cases just
because other fields needed different schema sides. The request fails before dispatch.

`0.11.0` is a breaking release: some calls admitted by `Request.Input`, including valid encoded
aliases beside mixed common fields, now fail instead of silently taking a default. Use a complete
schema side or a named mapping to decoded application values. The [version policy](../versions.md)
and [changelog](../changelog.md) cover updates.

On 0.10, invalid `page_size: "many"` with encoded `count` and decoded `offset` prepared the default
`25`. Valid `"05"` with the same mixed common fields also became `25`. On 0.11, those covered calls
fail with `SchemaError` before sending. Even `page_size: "25"` cannot rely on the default as a way
to bypass the supplied encoded input. A value's static admission does not mean the whole encoded
group passes its schema.

The check keeps the existing strict refusal, so its reported location can name another field that
failed that read. It does not add another schema evaluation to find a different error. Existing
defaults and the writer can run before refusal; their effects are not undone.

## Bounds and remaining work

This extends the [0.9 root-name proof](./0.9.md) to the actual successful final fieldwise route,
including a winning root union-member route. Stable plain input, finite closed root names, a
supplied encoded-only name, no supplied decoded-only name and actual strict encoded output are still
required. The preceding whole decoder must actually have failed. Individual property reads do not
establish that route.

Whole/member constructor and decoder choices keep their priority. Writer-failure fallback, schema
errors, defects, interruption, services, raw defaults and fields held by other bindings retain their
existing behavior. The check does not replay decoding, rebuild encoded input from prepared output,
or infer an alias map or equality rule for arbitrary transformed values.

On 0.11, this does not solve visible nested defaults: an optional renamed finite limit inside an
unchanged `filter` object can still turn `filter: { page_size: "many" }` into a default.
[0.12](./0.12.md) narrows this limit for stable direct-object paths after successful initial whole
construction and strict writing. Member-constructor and other unsupported or ambiguous proof routes
also remain under [#170](https://github.com/viell-dev/slop-effect-schema-http/issues/170). Use
decoded names or a named decoded mapping there. The broader [schema/raw-input
gaps](https://github.com/viell-dev/slop-effect-schema-http/issues/143) include pre-existing
union/sibling selection refusals; schema-owned reading inside opaque values remains separate.
[Limits and recovery](../limits.md) gives the supported checks and workarounds.
