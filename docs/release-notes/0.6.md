# What's in 0.6

Runtime changes: this release checks a later raw edit against a generated renamed field, then adds
separate stacked-union and opaque-neighbor recoveries in patches. The empty caller group is the
decisive condition for the renamed-default check; this is not the invalid caller-alias repair
introduced in 0.9.

`0.6.0` is a breaking release because more overwritten raw edits fail with `Request.InvalidRequest`.
Read the migration below before updating from `0.5`. The [version policy](../versions.md) covers
installation and updates, and the [detailed changelog](../changelog.md) records the changes.

`0.6.2` is a compatible patch that keeps annotations during union recovery. The earlier `0.6.1`
patch adds the bounded constructor recovery described below. The `0.6.0` migrations still apply when
updating from `0.5`.

Compare the [related release family](./index.md#schema-input-hardening); use [Schema-backed
input](../schema-input.md) and [Schema-backed groups](../schema-groups.md) for today's contract and
active limits. The running schema below makes the changed route, container or layer directly
comparable with the previous release.

On `0.5`, compiling `overwritten` with `{}` sent `?page_size=25`, silently replacing the later raw
`5`. On `0.6`, it fails before dispatch and names `page_size`.

The new proof applies when the decoded and encoded schema shapes are closed objects and the caller
group is an ordinary or null-prototype object with no own keys at all, including non-enumerable and
symbol keys. Every declared decoded and encoded name must also be absent from its prototype chain.
Successful non-iterable output must actually hold the edited encoded field. The check uses that
result without evaluating a schema, getter or iterator again.

This includes an omitted group, which is validated as `{}`. Any supplied caller field disables this
new proof, even an unrelated field the schema would strip. Classes, unions, open endpoints and
inherited/accessor input remain outside it. The existing direct same-name proof still applies where
it already did.

On `0.5`, this call fails because the union first keeps only `b`. On `0.6`, its recovery can choose
the member holding `a` and `c`, leaving `b` with the binding that actually took it. Query and header
groups use the same rule. A name that a sibling merely allows supplies no evidence that it kept a
caller field.

Recovery starts only when the normal path would refuse uncovered fields at the group level. It
retries the whole union on the original input, keeping every member and the existing input-side
priority. It preserves earlier field-consumption evidence, so changing one selection cannot withdraw
a field another binding already relied on.

These attempts can evaluate defaults, checks and transformations again, require their services, or
fail. Existing calls that already kept their fields use their original path. Recovery is bounded to
eligible unions of closed struct members; annotations are kept. Union-parent checks,
context/defaults or encoding, transformed or iterable groups, nested losses and joint backtracking
remain outside it. Schema-validation failures can be skipped; when no alternative qualifies, the
original field refusal remains. Exceptions and defects are not swallowed. Bind the intended member
directly when the definition needs a particular choice.

## Since 0.6.1: keep visible fields beside an opaque value

A stray key inside an opaque `Option` or `Map` can make a strict whole-object read fail. The loose
read can then choose a narrower visible union member, refusing a caller field that a wider member
could keep. This closed struct is one such case:

<<< ../../examples/opaque-neighbor.ts#opaque-neighbor

When the original reader would refuse a nested visible field, a direct closed struct can try its
supplied fields through their constructors. Visible fields use strict construction; a direct opaque
declaration without an encoding uses its ordinary construction. The original parent constructor and
writer still validate the whole result strictly, including parent checks and defaults. Recovery
accepts only an output that preserves the caller's visible fields. It does not change a call that
already succeeded.

This attempt uses constructors only. If another field needs decoding, it retains the original
refusal rather than choose a different side for an ambiguous transform. JSON text, transformed or
open parents, shared object references and object values under empty or open schemas such as
`Schema.Unknown` remain outside this recovery. Accessor, inherited, nonplain or suspended structures
prevent a stable capture. New attempts can repeat schema effects, require their services, or fail. A
typed failure keeps the original refusal; defects and interruption propagate. The schema's own
reading still applies inside opaque values.

Visible input changed after creating its encoding Effect also retains the original refusal, so a
retry cannot use a stale copy. Create a fresh encoding Effect after changing that input.

successful reads keep their original schema-evaluation path; newly attempted alternatives can repeat
schema effects or fail.

## Remaining boundaries

The library still cannot infer general correspondence through group transformations or resolve
conflicting decoded/encoded aliases. A nonempty renamed group can therefore retain the old raw-edit
limit. Opaque-neighbor cases outside constructor recovery and broader joint union selection remain
tracked in [#143](https://github.com/viell-dev/slop-effect-schema-http/issues/143). Inside opaque
values, the schema's own reading applies. The [Request guide](../modules/request.md) and [Limits and
recovery](../limits.md) describe the complete contract.
