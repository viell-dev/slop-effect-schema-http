# What's in 0.17

Effect Schema HTTP `0.17.0` recognises Effect's own nested forms of primitive alternatives, such as
`Schema.Literals([...])` and `Schema.NullOr(Schema.String)`, when it validates constructor aliases.
An invalid encoded alias beside one of them now refuses before dispatch instead of being replaced by
an optional constructor default. Formerly successful calls can therefore fail, so this is a breaking
release. It extends the [0.16 alternative rule](./0.16.md#validate-optional-object-alternatives) and
does not finish [#170](https://github.com/viell-dev/slop-effect-schema-http/issues/170).

Use [Schema-backed input](../schema-input.md) for the complete current contract and retained limits.
The [release family](./index.md#schema-input-hardening) places this change among the earlier
constructor-default extensions. The [changelog](../changelog.md) also records the Effect 4.1.3 and
4.1.4 verification that this release carries; the supported peer floor remains 4.0.7.

## Validate aliases beside literal and nullable alternatives

0.16 treated an unencoded primitive union member, such as `Schema.Literal("all")`, as an alternative
that cannot hold an object. Effect builds `Schema.Literals`, `Schema.NullOr` and `Schema.NullishOr`
as unions of their own, so a member written with them was not recognised. This filter reads finite
numbers from text, renames the field and gives construction a default; each item is either a filter
or a keyword:

On 0.16, `invalid` prepared `[{"page_size":"25"}]`: the caller's `"many"` was replaced by the
default. On 0.17 it fails with `SchemaError` before dispatch, as the flat
`Union([Schema.Literal("all"), Schema.Literal("none"), Filter])` already did. Both valid calls
prepare `[{"page_size":"5"}]`, the isolated omission prepares `[{"page_size":"25"}]`, and the
keywords keep their own values.

The rule applies at any depth and at every level the 0.16 rule covers: the root, array and tuple
elements, and eligible object and parent-union ancestors. A nullable text alternative of an ancestor
field works the same way:

<<< ../../examples/migration-0-17.ts#nullable

On 0.16, `invalidCell` prepared `{"cell":{"filter":{"page_size":"25"}}}`. On 0.17 it refuses; the
text alternative still sends `{"cell":"x"}`. A codec whose closed object encoding view includes such
an alternative, such as `Union([Struct, Schema.Literals([...])])`, establishes the same evidence.

The refusal names the alias as an excess property, such as
`Expected no excess property at [0]["page_size"]`: when the additional whole decoder fails,
preparation keeps the original strict refusal, as in 0.16. For field-value feedback under your
form's names, validate an [explicit decoded mapping](./0.16.md#validate-a-decoded-mapping) before
preparation.

## Supply a complete side

The additional validation reads the whole value, so it also reaches arrays that mix encoded-only and
decoded-only items, even when every item is valid:

On 0.16, `mixed` prepared `[{"page_size":"25"},{"page_size":"5"}]`: the valid `"05"` was replaced by
the default. On 0.17 it refuses with `SchemaError` at the decoded item, as the flat alternative
already did. `encodedSide` prepares `[{"page_size":"5"},{"page_size":"5"}]` and `decodedSide`
prepares `[{"page_size":"5"},{"page_size":"7"}]`. Supply every item on one side, as the [0.16
article](./0.16.md#supply-a-complete-side) describes.

## Update

1. Search input schemas for `Schema.Literals`, `Schema.NullOr`, `Schema.NullishOr` or nested
   `Schema.Union` members beside an object whose renamed field has a constructor default.
2. Calls that sent invalid encoded aliases now fail with `SchemaError` before any request. Correct
   the input, or validate it before preparation and supply decoded values.
3. Calls that mixed encoded-only and decoded-only items in one value now fail too. Supply every item
   on one side.
4. Valid values supplied on one side, omissions and the alternatives' own values need no change.

## Bounds and remaining work

A union counts only when it has no encoding and every member qualifies: String, Number, Boolean,
BigInt, Symbol, UniqueSymbol, Literal, Enum, TemplateLiteral, Null, Undefined, Never, or another
such union. A union of primitives alone still supplies no object view.

Encoded alternatives remain outside the rule, even when both sides are text. Beside
`Schema.FiniteFromString`, an invalid alias still prepares the default:

<<< ../../examples/migration-0-17.ts#encoded-alternative

`stillDefaulted` prepares `[{"page_size":"25"}]`, as on 0.16. Void, open/opaque/suspended members,
unions with any other member and array-shaped parent members also remain excluded. A Void member
accepts any value on the decoded side, which preparation tries first. Placed after an object member,
it can take even a valid encoded object and write `undefined` (`null` in JSON); placed first, it
takes every object. Leave Void out of input schemas.

An invalid alias supplied together with its decoded name, such as `{ limit: 5, page_size: "many" }`,
is still a [conflicting-alias limit](../schema-input.md#active-limits-and-recovery): the decoded
name wins. The remaining container, iterator and normalized-declaration exclusions of 0.16 are
unchanged.
