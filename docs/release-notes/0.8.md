# What's in 0.8

Effect Schema HTTP 0.8 keeps the encoded input type of a partly renamed schema. A shared optional
field no longer makes TypeScript discard the side with the renamed keys. Calls that already work at
run time can now compile with their encoded input.

`0.8.0` is a breaking release because helpers using `Request.Input` can now receive the encoded
shape as well as the decoded one. A helper that reads only a decoded field name may need a narrower
input declaration or a check for which shape it received. The [version policy](../versions.md)
covers updates, and the [changelog](../changelog.md) records the changes.

On `0.7`, TypeScript rejected `page_size` in the encoded call. On `0.8`, both calls compile and send
`?page_size=5`. The same repair applies through unions and the public `Request.Input` type. Required
fields and each side's value types still apply; this does not allow arbitrary extra names or values.

## Give a helper the input it actually accepts

A helper that accepted `Request.Input<typeof Filters>` and read `input.limit` previously compiled
because the encoded side was missing. Now its input can contain `page_size` instead, so that
property access fails the compiler's check.

explicitly. A named input mapping can then supply the request's decoded input:

`search` accepts `{ limit: 7 }` and sends `?page_size=7`; an empty input sends the schema-compatible
default `25`. If a helper really accepts `Request.Input`, handle both schema sides rather than
assuming the decoded name is present. Whole-side lists and opaque value types retain their existing
constraints.

## Existing behavior and limits

This repair changes types only. The schema reader, constructor and decoder priority, defaults,
validation and request bytes are unchanged. The earlier [0.7 migration](./0.7.md) still applies to
generated fields and raw edits.

An invalid value under a renamed encoded name can still be replaced by an optional constructor
default ([#170](https://github.com/viell-dev/slop-effect-schema-http/issues/170)). Use decoded input
or a decoded input mapping for those schemas until that separate runtime repair is delivered. The
new typing support does not fix that validation defect or the broader [tracked schema
gaps](https://github.com/viell-dev/slop-effect-schema-http/issues/143).
