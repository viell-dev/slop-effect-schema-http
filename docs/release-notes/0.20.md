# What's in 0.20

Effect Schema HTTP `0.20.0` carries 0.19's rule into `Option` values: a supplied value is kept, or
the request is refused before dispatch with an error naming it. On 0.19, several readings of an
`Option` could still lose part of a value without refusing. Four groups of change follow from it:

- **Option payloads.** A field the payload's schema states, such as `limit` in a wider union member,
  is kept where 0.19 left it out or refused, and a key no member states is left out, as Effect
  leaves it out.
- **Native Option wrappers.** An `Option.some` or `Option.none` given where the encoded payload
  belongs is read through its decoded side, kept, or refused, where 0.19 could send `{}`.
- **Built-ins and `oneOf`.** A `Date`, `Map` or other built-in that a struct would rebuild from its
  fields refuses, and a fieldless value several `oneOf` members read refuses as ambiguous.
- **Messages.** A refusal says why a field cannot be kept where its names or place show why.

Formerly successful calls can fail or send a different request, so this is a breaking release. Calls
that supply plain data on its decoded side, or one complete encoded side, and give each `Option` as
Effect types it, send what they sent on 0.19, apart from the Option payloads and `oneOf` unions
below. The [changelog](../changelog.md) has every change with its issue, and [the input
reference](../schema-input.md) states today's rules.

Each 0.19 result below was measured on the published `0.19.0` with Effect 4.1.4.

## Expect an Option's payload to keep its stated fields

<<< ../../examples/migration-0-20.ts#payload

| Call         | 0.19                                    | 0.20                                 |
| ------------ | --------------------------------------- | ------------------------------------ |
| `inList`     | `{"held":[{"owner":"a"}]}`              | `{"held":[{"owner":"a","limit":5}]}` |
| `configured` | refused at `["held"]["value"]["limit"]` | `{"held":{"owner":"a","limit":5}}`   |
| `competing`  | refused at `["held"]["value"]["limit"]` | `{"held":{"owner":"a","limit":5}}`   |

`stray` is stated by no member, so it is left out, as a bare payload leaves it out. 0.19 read the
payload through the narrowest member that accepted it once `stray` made the strict reading fail, so
in a list, a nested `Some` or a same-tag union `limit` went with it
([#305](https://github.com/viell-dev/slop-effect-schema-http/issues/305)). A configured
`OptionFromOptionalNullOr`, and codecs competing at one position that share one payload schema, now
read the payload as `OptionFromNullOr` reads it
([#312](https://github.com/viell-dev/slop-effect-schema-http/issues/312)). A class instance
elsewhere in the body no longer makes a wider field refuse
([#308](https://github.com/viell-dev/slop-effect-schema-http/issues/308)).

Some calls that sent on 0.19 now refuse:

- A field that a relaxed reading forced by some other failure would lose is refused, naming it,
  rather than left out. Remove the keys that prevent the strict reading, or bind the intended union
  member directly.
- A same-tag payload can refuse when no member holds every stated field it was given.
- A wire name such as `page_size` inside a nested `Some` refuses at
  `["held"]["value"]["inner"]["value"]["page_size"]`, where 0.19 left it out and sent
  `{"held":{"inner":{}}}`. Give the decoded name `limit` inside a `Some`.

A field stated only by a member that a literal tag such as `kind` rules out is now left out, as for
a bare payload, where 0.19 refused it. Validate the intended variant yourself if you relied on that
refusal.

## Give an Option on one side

An `Option` is decoded data. Its wire position holds the encoded payload or its absence:

<<< ../../examples/migration-0-20.ts#wrapper

| Call          | 0.19                      | 0.20                                        |
| ------------- | ------------------------- | ------------------------------------------- |
| `beside`      | `{"held":{},"count":"2"}` | `{"held":{"a":"a","b":"keep"},"count":"2"}` |
| `atWireName`  | `{"wire_held":{}}`        | refused, `Missing key at ["held"]`          |
| `decodedSide` | `{"wire_held":{"a":"x"}}` | unchanged                                   |
| `encodedSide` | `{"wire_held":{"a":"x"}}` | unchanged                                   |

`count: "2"` is on the encoded side, so 0.19 read the whole value as encoded and wrote the `Some` as
an object with no fields of the payload. A struct now reads each field on its own side there, so a
valid `Some` or `None` beside an encoded sibling is kept
([#318](https://github.com/viell-dev/slop-effect-schema-http/issues/318)). A `Some` whose payload is
invalid, such as `Option.some({ a: 5 })`, refuses at `["held"]["value"]["a"]` where 0.19 sent
`{"held":{}}` ([#309](https://github.com/viell-dev/slop-effect-schema-http/issues/309)). This holds
for hand-written codecs and for open payload schemas such as `Schema.Any` too
([#319](https://github.com/viell-dev/slop-effect-schema-http/issues/319)).

`atWireName` puts a `Some` under the wire name of a renamed field, a position that holds the encoded
payload. It does not type-check, and it reaches preparation from untyped data. 0.19 sent
`{"wire_held":{}}`; 0.20 refuses it, also beside a renamed sibling, below a renamed ancestor,
through a suspension or a recursive schema, a renamed class, and a list or union below the rename
([#321](https://github.com/viell-dev/slop-effect-schema-http/issues/321)). The message can read
`Missing key` at the decoded name
([#313](https://github.com/viell-dev/slop-effect-schema-http/issues/313)). Give the field on its
decoded side, as `held`, or its encoded payload at `wire_held`.

Under a `oneOf` that lists the Option's struct before one that reads the same field as a plain
struct, a `None` beside an encoded sibling now refuses as ambiguous, where 0.19 sent `{"held":{}}`.

## Keep a payload's own `value`

<<< ../../examples/migration-0-20.ts#inner-value

0.19 sent `{"held":{"value":{"a":"outer"}}}` for `collision`: the outer `a`, which the chosen member
does not state, replaced the payload's own `value.a`. A payload's `value` field and the `Some`
wrapper are now kept apart
([#299](https://github.com/viell-dev/slop-effect-schema-http/issues/299)). Where one member states
the field, `value.a` stays `"inner"`; where the position cannot tell, as here, the collision refuses
at `["held"]["value"]["a"]`. Remove the unstated outer key, as `inner` does, or rename the payload's
`value` field. A `Some` supplied as a struct beside an Option alternative can refuse the same way;
supply a plain object there.

## Convert built-ins to plain data

<<< ../../examples/migration-0-20.ts#built-ins

0.19 sent `{"held":{}}` for `date`, as Effect's own encoding does for a struct. 0.20 refuses with
`The schema cannot keep this Date as an object at ["held"]`, as 0.19 already did for records
([#316](https://github.com/viell-dev/slop-effect-schema-http/issues/316)). The same holds under
`Schema.NullOr` and `Schema.OptionFromNullOr`, and for a `Map`, `Set`, `RegExp`, `Error`, `URL` and
the other values the record check refuses. Class instances with fields, typed arrays, `Option` and
`Result` values and plain objects are read by their own fields as before, and an empty struct keeps
the value as given. Convert the value first, or give the field a schema such as `Schema.Date`.

## Choose a member for a fieldless value

<<< ../../examples/migration-0-20.ts#one-of

Both members read `{}`. 0.19 chose `Schema.Void` by member order and sent `{"f":null}`; 0.20 refuses
`ambiguous` with `Expected exactly one member to match at ["f"]`
([#276](https://github.com/viell-dev/slop-effect-schema-http/issues/276)). The same applies to an
empty list, and to two structs whose fields are all optional, even if one has a constructor default.
The refusal can be a `SchemaError` where a handler expected `InvalidRequest` or `HttpBodyError`,
including for an omitted or stacked query or header group. Supply a value only the intended member
accepts, as `chosen` does, or use `anyOf` for first fit. An enclosing union can still read the whole
value through another member, so the wire can now hold `{}` or `[]` where 0.19 sent a defaulted
object or `null`.

## Write a class instance through its class

<<< ../../examples/migration-0-20.ts#class

`Counted` holds a member of its own, `tally`, so its instances cannot be written strictly. 0.19
tried `Loose` first, which strips the instance, and refused with `SchemaError`. 0.20 writes the
instance through its class and sends `{"a":"item"}`, or `{"A":"item"}` with renamed fields, at the
root, in a field or list item and below a renamed parent
([#274](https://github.com/viell-dev/slop-effect-schema-http/issues/274)). It still refuses where
the class cannot write the instance whole, and where another field is written under the same wire
name. Elsewhere in such a request, `Schema.Option(X)` still uses Effect's first-fit member
selection, which can leave out a field only a wider member of `X` holds. Bind that member directly
where the field is required.

## Read the new messages

<<< ../../examples/migration-0-20.ts#messages

| Call             | 0.19                                                                              | 0.20                                                                                                |
| ---------------- | --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `bothNames`      | `The schema cannot keep this field with the rest of the value` at `["page_size"]` | `This field is given under both "limit" and "page_size"; give it under one name` at `["page_size"]` |
| `decodedInvalid` | `The schema cannot keep this field with the rest of the value` at `["limit"]`     | `Expected number` at `["limit"]`                                                                    |

Every call that refused on 0.19 for this reason still refuses before dispatch with the same error
class, and every call that sent still sends the same bytes; only the messages and paths change
([#275](https://github.com/viell-dev/slop-effect-schema-http/issues/275)). Items of a list, tuple or
record on different sides, and a built-in where a record would rebuild it, have their own messages
too, and a refusal beside a `Schema.Void` no longer names a valid neighbour. Where nothing more is
known, the generic message stays. Code that matches the text of these refusals needs updating. A
refusal stores no value the caller gave; a message the schema's author wrote is shown as written, as
on any other schema failure.

## Update

```sh
npm install viell-effect-schema-http@0.20.0
```

Before updating, look for:

- `Option` payloads that can hold keys no member states beside a wider member's field, including in
  lists, nested `Some` values, same-tag unions and configured `OptionFromOptionalNullOr` codecs.
- Untyped input that can put an `Option.some` or `Option.none` at a renamed field's wire name, or
  beside a field given on its encoded side.
- `Option` payloads with a field called `value`.
- `Date`, `Map` and other built-ins given where a struct reads an object.
- `oneOf` unions whose members can all read `{}` or `[]`.
- Code that matches the text of refusal messages.

Add a request test for each. Most such calls now refuse before dispatch, with an error that names
the value; Option payloads and class instances can send a different body instead.

## Also in 0.20

- A schema's decoders and checks run as often as on 0.19. A development build ran them more often
  while working out the new messages; no release carried that
  ([#317](https://github.com/viell-dev/slop-effect-schema-http/issues/317)).
- Checking visible payloads in unwrapping codecs adds preparation work, measured in
  [#298](https://github.com/viell-dev/slop-effect-schema-http/pull/298).
- The [Transport guide](../modules/transport.md) tells authors of providers that write bytes to
  refuse header names that are not tokens, and NUL in header values
  ([#302](https://github.com/viell-dev/slop-effect-schema-http/issues/302)). The library still
  passes them on; `fetch` and `node:http` keep them off the wire.

## Bounds

[Limits](../schema-input.md#active-limits-and-recovery) lists what preparation cannot see, with the
reason. Those that concern this release:

- `Schema.Option(X)` and payloads with an encoding of their own beside `OptionFromOptionalKey` stay
  opaque, and codecs competing with different payload schemas keep 0.19's reading, which can leave
  out `limit` beside a stray key
  ([#312](https://github.com/viell-dev/slop-effect-schema-http/issues/312)).
- A nested `None` below fields that an integer-key rename cannot tell apart is still sent as `{}`
  ([#328](https://github.com/viell-dev/slop-effect-schema-http/issues/328)), and a hand-written
  codec spelled like a built-in one is read as that codec
  ([#327](https://github.com/viell-dev/slop-effect-schema-http/issues/327)).
- For an object with an undefined-valued key, an enclosing `oneOf`'s order or a stray key in an
  opaque sibling can still decide whether a JSON field is sent as `null` or `{}`
  ([#310](https://github.com/viell-dev/slop-effect-schema-http/issues/310)).
