# What's in 0.9

Initial runtime repair of the alias/default-loss family (#170): a caller supplies an encoded name,
construction ignores it and generates a default, and the supported root path now validates that
supplied value. This concerns caller input, unlike 0.6/0.7's later raw edits. It is a bounded
repair, not completion of the family.

`0.9.0` is a breaking release: some calls that previously sent a default now fail with
`SchemaError`. The repair also keeps a valid encoded value when a separate stacked binding holds
another field. The [version policy](../versions.md) covers updates, and the
[changelog](../changelog.md) records the changes.

Compare the [related release family](./index.md#schema-input-hardening); use [Schema-backed
input](../schema-input.md) and [Schema-backed groups](../schema-groups.md) for today's contract and
active limits. The running schema below makes the changed route, container or layer directly
comparable with the previous release.

On `0.8`, evaluating `invalid` sent `?page_size=25`. On `0.9`, it fails with `SchemaError` before
any request is sent. Evaluating `valid` sends `?page_size=5`, and evaluating `omitted` still sends
`?page_size=25`. The same repair applies to header groups and finite closed unions of these shapes.

For these inputs, defaults fill an omitted or `undefined` field. They do not make an invalid
supplied encoded value valid. If an application used the old substitution as a fallback, make that
policy explicit before calling the request, and validate the result. The existing
constructor/default and writer can run before the additional encoded validation; the repair does not
undo their effects. Their existing failures, ordinary decoded input and omission keep their
behavior.

## Bounds and remaining work

The additional check covers stable plain data objects whose decoded and encoded root field names
come from finite closed object or union shapes. A supplied encoded name must be absent from every
decoded member, and the input must not also supply a decoded-only name. After a typed strict read
failure, the initial whole constructor and strict write must succeed and actually write that encoded
name. Otherwise its existing result and priority stay in place. Already successful strict reads keep
their existing path.

Ambiguous names, both aliases supplied together, open or opaque group shapes, class or suspended
group schemas, iterable groups, inherited/accessor fields and changing input do not establish this
additional proof. The 0.9 check also left initial constructor failure followed by member or
fieldwise recovery outside it: an invalid `page_size` beside one encoded and one decoded numeric
field could take a default. [0.11](./0.11.md) narrows that limit for eligible final fieldwise
routes, without replaying effects; member-constructor and unsupported routes remain. The earlier
default substitution can remain outside the proof
([#170](https://github.com/viell-dev/slop-effect-schema-http/issues/170)); use decoded names or the
named mapping above. This does not establish nested alias correspondence or change the schema's
reading inside opaque values. [0.12](./0.12.md) adds eligible nested direct-object paths after
successful initial whole construction and strict writing.

The [0.8 input-helper migration](./0.8.md) still applies. Nested encoded-alias typing remained
separate work in 0.9 ([#172](https://github.com/viell-dev/slop-effect-schema-http/issues/172));
[0.10](./0.10.md) retains those whole encoded shapes and explains the nested helper migration. The
broader [schema/raw-input gaps](https://github.com/viell-dev/slop-effect-schema-http/issues/143)
remain separate from both repairs.
