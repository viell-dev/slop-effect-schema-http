# What's in 0.1

Effect Schema HTTP 0.1 lets an application describe the parts of an HTTP service it uses, then
encode requests and decode responses with Effect Schema. The server can be written in any language
and does not need to know about this library.

The current package is `0.1.0-rc.1`, a release candidate for the first stable release. This article
introduces the API available in that candidate. The [version policy](../versions.md) explains
installation and updates; the [detailed changelog](../changelog.md) records individual fixes and
maintenance work.

## Contracts belong to your application

You can define just the input and output your application needs, even for an existing external
service. A user update can accept `{ path: 42, body: { name: "Grace" } }`, send a PATCH request with
a JSON body, and return a validated `{ id: number, name: string }`.

[Describe and execute a request](../usage.md) builds that operation alongside a deletion, sharing
the base URL and user path. Schema encoding happens before dispatch, so input that cannot be encoded
fails before an HTTP request is sent.

## Request and response formats compose

[Request](../modules/request.md) binds typed path, query, header and body input.
[Body](../modules/body.md) supports finite JSON, text, byte, URL-encoded form and multipart
representations. A JSON codec can be reused for an outgoing body or a returned value; the method,
status and other request/response choices remain explicit.

This keeps a shared service model separate from endpoint behavior. Creating a user can accept only a
name and return an assigned ID, while updating that user also needs an ID in the URL.

## Model the responses your application understands

An HTTP response is more than a successful status. A lookup may return a record or a missing-record
answer; both can be meaningful application results. [Response](../modules/response.md) selects
ordered cases and can tag their decoded values so callers distinguish those outcomes.

Unexpected statuses and bodies that do not match the selected schema produce different failures.
[Operation](../modules/operation.md) can then transform a decoded result or turn a recognized
business outcome into an application error.

## Use your own HTTP client

Operations run through the Effect HTTP client supplied by the application. The same contract can use
Fetch for a real service or an in-memory client for a test. Client middleware, credentials and
browser policy remain under the application's control.

Retries are opt-in. [Policy](../modules/policy.md) describes retry and timeout behavior, while
[Interaction](../modules/interaction.md) coordinates calls that should share work or supersede one
another. Neither makes an unsafe mutation safe to repeat.

## Start with one operation

[Getting started](../getting-started.md) installs the package and runs a complete POST example. The
[module guides](../api.md) cover the rest of the API, and [Limits and recovery](../limits.md)
explains the supported environments and failure boundaries. Bodies are finite; streaming, server
generation and a general cache are outside this release.
