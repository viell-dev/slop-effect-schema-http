# What's in 0.15

Effect Schema HTTP `0.15.0` fixes array normalization: retain actual array keys and length and avoid
converting symbols to numbers. This is a different layer from 0.14's constructor-default evidence.
It does not extend or finish #170; removing accidental failures can expose its existing unsupported
defaults.

This is a breaking release: corrected positions can change successful output, and removing an
accidental failure can expose an existing constructor default on an unsupported input. The [version
policy](../versions.md) covers updates; the [changelog](../changelog.md) records details.

Compare the [related release family](./index.md#schema-input-hardening); use [Schema-backed
input](../schema-input.md) and [Schema-backed groups](../schema-groups.md) for today's contract and
active limits. The running schema below makes the changed route, container or layer directly
comparable with the previous release.

## Bounds

Where the schema exposes array positions, normalization keeps actual keys and length when it needs a
rewritten array; an unchanged value retains its identity. Numeric cells include schema-readable own
hidden and inherited positions. Metadata is not looked up as an element type. Normal processing may
still read getters and inspect prototypes; this is not a zero-getter or zero-effect guarantee. Fully
own positions need no prototype walk. Missing positions can require inspecting prototypes to retain
inherited cells; errors from that reflection propagate as defects, including from a proxy's
`getPrototypeOf` handler. A sparse proxy previously accepted after compaction can therefore fail if
that handler throws. An incoherent proxy that reports an own index beyond its length cannot be
copied into a native array with the same layout. It keeps its original reading route, which can
refuse; normalization does not manufacture a larger array to hold the virtual position.

Hidden/inherited-position discovery applies to structural array views without open or opaque
alternatives. A union's Array member does not authorize inspecting a value that Unknown, Any,
ObjectKeyword or a declaration can retain. Such mixed views keep their existing enumerable-child
normalization; the library does not execute their checks or services to choose a normalization view.
They do not gain a general preservation proof. A rewritten mixed array uses its own length
descriptor without adding a length-getter read before the schema chooses its route.

Constructor/decoder, strict-success, fieldwise and writer-fallback priorities stay in place. No
public type, dependency, constructor replay, alias correspondence or arbitrary equality is added.
The [0.14 migration](./0.14.md) still explains the bounded dense-array proof and its whole-reading
consequences. Broader [#143 schema/input
gaps](https://github.com/viell-dev/slop-effect-schema-http/issues/143) and
[limits/recovery](../limits.md) remain separate.
